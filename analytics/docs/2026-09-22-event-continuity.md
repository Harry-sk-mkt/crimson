# 연속 참석(저번 이벤트도 보고 이번 이벤트도 보는 단골) (2026-09-22, 1차)

사용자 요청: 단골(regular)을 "저번 주 웨비나도 보고 이번 주 웨비나도 보는" 연속성 관점에서 본다. 코드: `src/event_continuity.py` (테스트 포함).

## 방법과 범위

- 멤버 리포트에는 이벤트 날짜가 없어서, 날짜가 있는 사용자 제공 이벤트 일정표(14개)와 캠페인 이름으로 매칭한 이벤트만 썼다. 14개 모두 매칭됐다.
- 2025: 07/05, 07/19, 07/23, 07/26, 07/30, 08/13 (6개). 2026: 07/11, 07/18, 07/22, 07/29, 08/05 (5개).
- 제외: 2025-08-23(미국 공동, 사용자 기준), 2025-08-02(Contact 멤버 4행뿐인 소규모, **내 판단이며 사용자 확인 전**).
- 2026 8/8 레코딩은 같은 주제의 8/5 라이브와 한 이벤트로 합쳤다 (**내 판단, 사용자 확인 전**). 합치지 않은 민감도 분석도 했다.
- 대상은 이벤트에 `Attended`한 Contact다. Lead는 멤버 단위 데이터가 없다.

## 결과

| 지표 | 2025 | 2026 | 변화 (근사 p) |
|---|---|---|---|
| 직전 이벤트 참석자 중 **바로 다음 이벤트도 참석** | 70/235 (30%) | 19/90 (21%) | -9pp (p≈0.12) |
| 2개 뒤 이벤트에도 참석 | 60/200 (30%) | 10/61 (16%) | -14pp (p≈0.04) |
| 3개 뒤 이벤트에도 참석 | 40/166 (24%) | 10/48 (21%) | -3pp (p≈0.64) |
| **이번 이벤트 참석자 중 직전 이벤트도 본 사람** | 70/210 (33%) | 19/98 (19%) | -14pp (p≈0.01) |
| 참석자 중 연속 2회+ | 40/153 (26%) | 13/88 (15%) | |
| 참석자 중 연속 3회+ | 15/153 (10%) | 4/88 (5%) | |
| 이벤트당 참석 Contact (평균) | 약 46명 | 약 22명 | |

- 연속 참석은 모든 지표에서 2026이 낮다. 가장 분명한 것은 "이번 참석자 중 직전에도 온 사람의 비중"으로 33% → 19%다. 청중에서 이어 보는 사람의 비중이 크게 줄었다는 뜻이다.
- 2025에는 바로 다음(30%), 2개 뒤(30%), 3개 뒤(24%)로 거리가 멀어져도 비율이 크게 안 줄었다. 단골이 "바로 이어서"보다 "자주" 왔다는 뜻이다. 2026도 21%/16%/21%로 평평하지만 낮다.
- 이벤트 쌍별로는 2026 07/29→08/05가 14%(4/29), 07/18→07/22가 15%(4/26)로 낮고, 07/22→07/29는 46%(6/13)로 높다. 표본이 작아 개별 쌍은 잡음이 크다.
- 레코딩을 합치지 않아도 결과는 같다 (모든 인접 쌍 21/103 = 20%).

## 앞선 분석과의 관계

- 연도 단위 유지율(`2026-09-22-regulars-retention.md`): 전년 참석자의 다음 해 재참석률 38% → 22%.
- 이벤트 단위 연속성(이 문서): 이번 청중 중 직전에도 온 사람 33% → 19%.
- 두 관점이 같은 방향이다. "레귤러가 빠졌다"는 믿음과 일치한다. 다만 원인은 이 데이터로 알 수 없다.

## 한계

1. **통계적 증거는 약~중간이다.** p는 같은 사람이 여러 쌍에 들어가 독립이 아니라서 참고용이고, 지표가 4개라 다중비교도 걸린다. 방향이 모든 지표에서 같다는 점이 더 믿을 만한 근거다.
2. 이벤트가 2025는 6개, 2026은 5개뿐이고 간격이 다르다 (2025는 3~14일, 2026은 4~7일). 간격 7일 이하 쌍만 봐도 29% → 21%로 같다.
3. 이벤트당 청중이 절반으로 줄어서(46 → 22명) "다음 이벤트 참석"의 기회 자체가 작아졌다. "단골이 사라졌다"와 "이벤트가 작아졌다"는 이 데이터로 분리되지 않는다.
4. 일정표가 최근 4주 이벤트만 담아 6~8월 전체 이벤트의 일부다. 나머지는 날짜가 없어 못 썼다.
5. Contact 정의(예전에 한 번이라도 상담)와 조회 시점 문제는 그대로다 (`background.md`).
6. Lead는 이벤트별 멤버 단위 데이터가 없어 Lead의 연속성과 비교하지 못했다.

## 사용자 확인 대기

- 2025-08-02 이벤트(Contact 멤버 4행)를 뺀 것과, 8/8 레코딩을 8/5 라이브와 합친 것이 맞는가.
- 6~8월 전체 이벤트의 날짜(Salesforce 캠페인의 Start Date 컬럼을 리포트에 추가하면 됨). 전체 날짜가 있으면 이벤트 수를 늘려 신뢰도를 높일 수 있다.
